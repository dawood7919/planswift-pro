# استعادة واجهة الدخول عند توقف طلب الجلسة

تعتمد صفحات المشاريع ومساحة العمل على الاستعلام العام `auth.me` لمعرفة الجلسة الحالية. عند تعذر هذا الطلب سابقاً على مستوى الشبكة، كان من الممكن أن تبقى الواجهة في skeleton لأن حالة الاستعلام تظل تحميلًا حتى انتهاء الاتصال خارجياً.

أضيفت الآن مهلة مقدارها **12 ثانية** إلى طلبات tRPC في العميل. عند انتهاء المهلة يُلغى الطلب بصورة صريحة، فتنتقل بوابة لوحة التطبيق من حالة التحميل إلى حالة قابلة للتعافي تتضمن رسالة عربية وزر **إعادة محاولة التحقق** وزر **تسجيل الدخول**. لا توجد محاولة تلقائية متكررة ولا مسار يتجاوز OAuth أو حالة nonce.

| الحالة | السلوك الجديد |
|---|---|
| استجابة جلسة صحيحة | يستمر المستخدم إلى مساحة العمل كالمعتاد. |
| انقطاع أو طلب متوقف | ينتهي الطلب خلال 12 ثانية، ثم تظهر رسالة وزر إعادة المحاولة. |
| جلسة غير موجودة | يبقى زر تسجيل الدخول متاحاً بدلاً من مؤشر تحميل مستمر. |
| Cloudflare أو مزود OAuth الخارجي | لا يحاول التطبيق تجاوزه؛ يبقى العائق خارج التطبيق ويتطلب إتمام التحقق في صفحة الموفر. |

يؤكد اختبار `requestTimeout.test.ts` إلغاء طلب متوقف مع المحافظة على إرسال credentials في الطلبات السليمة. يعالج هذا التغيير واجهة Takeoff نفسها، ولا يدّعي إصلاح شاشة أو سياسة لدى موفر OAuth خارجي.
