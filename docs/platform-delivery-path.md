# مسار المنصات والتكاملات المؤسسية

## ما نُفذ الآن

أصبح تطبيق Takeoff قابلاً للتثبيت كـ **PWA** من المتصفحات التي تدعم ذلك. أضيف ملف manifest يعرّف الاسم والرمز ووضع النافذة وبداية التطبيق، كما سُجل service worker لحفظ غلاف التطبيق عند فشل الشبكة. يحتاج المتصفح إلى manifest لإظهار معلومات التثبيت مثل الاسم والرمز، وتتيح PWAs المثبتة نقاط تشغيل في Windows وAndroid عند دعم المتصفح والنظام [1] [3].

تعتمد مساحة الرسم على Pointer Events الموحدة، وتلتقط المؤشر عند بداية الرسم وتتعرف صراحةً على `pen` و`touch` و`mouse`. لذلك يمكن استعمال القلم المتوافق مع معيار المتصفح، مثل S Pen في المتصفحات الداعمة، من دون مسار لمس منفصل. يدعم المعيار معلومات إضافية كالميل والضغط، لكن Takeoff لا يستخدمها في الكمية الحالية لأن القياس الهندسي يعتمد الإحداثيات والمعايرة فقط [2].

| المجال | المنجز في الإصدار الحالي | حد النطاق الصريح |
|---|---|---|
| Windows | تثبيت PWA عبر متصفح داعم، نافذة مستقلة، شعار قابل للإخفاء (maskable) وغلاف مبسط عند انقطاع الشبكة. | ليس ملف MSI أو تطبيق Win32 أصلياً بعد. |
| Android / S Pen | تطبيق Kotlin أصلي بواجهة Jetpack Compose و`PdfRenderer` ومساحة رسم تميّز قلم S Pen واللمس، مع APK تجريبي يبنيه GitHub Actions؛ وتبقى PWA خياراً منفصلاً للويب. | لا تُستخدم قيمة الضغط أو الميل في حساب الكمية، ولا يمكن اعتماد القبول النهائي للقلم من دون جهاز فعلي مستهدف. |
| الويب | التطبيق الأصلي، استيراد PDF، قياس، تقارير، ملكية، وسجل تدقيق. | العمل دون اتصال محدود بغلاف التطبيق؛ تعديل البيانات يحتاج اتصال الخادم. |
| المؤسسة | حدود التصميم موثقة أدناه لتوحيد مسار التنفيذ. | لا توجد حالياً SAML أو SCIM أو RBAC مؤسسي متعدد المستأجرين. |

## خطة التكامل المؤسسي

يجب أن تسبق أية حزمة أصلية أو طرح مؤسسي طبقة هوية مستقلة عن جلسات الاختبار المرحلية. يبدأ المسار بإضافة موفر OIDC/SAML موثق، ثم تحديد أدوار المؤسسة وعضوية المشروع، ثم SCIM لإدارة المستخدمين، وأخيراً سجل تدقيق قابل للتصدير وسياسات الاحتفاظ بالبيانات. لا تُعد جلسة التحقق المرحلية بديلاً عن هذا المسار.

| المرحلة | العقد المطلوب | معيار القبول |
|---|---|---|
| الهوية | OIDC/SAML، نطاقات إعادة توجيه، MFA وسياسة جلسة. | دخول وخروج مؤسسيان واختبارات فصل المستأجرين. |
| التفويض | `organization` و`membership` وأدوار مشروع صريحة. | منع قراءة أو تعديل مشروع خارج العضوية، مع اختبارات تكامل. |
| الإدارة | SCIM ومجموعات IdP وتسجيل تدقيق للتغييرات. | مزامنة مستخدم وإبطال وصوله بصورة قابلة للمراجعة. |
| سطح المكتب | اختبار تثبيت Edge ثم تغليف اختياري عبر PWABuilder إذا تطلبت المؤسسة توزيعاً مُداراً. | تثبيت وتحديث وإلغاء تثبيت تحت سياسة إدارة الجهاز. |
| Android | توزيع APK أصلي عبر أثر GitHub Actions، ثم توقيع Release وAAB أو مسار MDM عند اعتماد التوزيع الإنتاجي. | اختبار قلم فعلي على أجهزة مستهدفة وإدارة تحديثات الحزمة. |

> لن يُضاف دعم الضغط أو الميل في القلم إلى حساب الكميات إلا إذا اعتمدت المؤسسة دلالة هندسية لهما. إبقاؤهما خارج المعادلة حالياً يحافظ على نتائج القياس الحتمية القابلة للتدقيق.

## التحقق المقترح بعد النشر

في Microsoft Edge، يفحص فريق الاختبار manifest وservice worker وتخزين cache من لوحة Application، ثم يثبت PWA ويعيد اختبار الفتح. توثق Microsoft أن هذه اللوحة تعرض manifest وservice workers وذاكرة التخزين، وأن PWAs المثبتة يمكن أن تظهر في قائمة Start على Windows [3]. على Android، يثبّت الفريق ملف APK الأصلي المبني من GitHub Actions، ويختبر الرسم باللمس والقلم مع ملف PDF فعلي، ثم يتحقق من عدم فقد النقاط عند `ACTION_CANCEL` أو تبديل اتجاه الشاشة.
