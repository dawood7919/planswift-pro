# قائمة قبول الأجهزة الفعلية

هذه القائمة تفصل بين ما تحقّق آلياً في CI وما لا يمكن إثباته إلا على جهاز فعلي. لا يُعلَّم قبول Windows أو S Pen نهائياً قبل تسجيل النتيجة لكل خطوة.

| المنصة | الإجراء | النتيجة المقبولة | دليل التحقق |
|---|---|---|---|
| Windows 10/11 + Edge | افتح `https://takeoffweb-mxdy4ywn.manus.space` ثم ثبّت Takeoff من قائمة التطبيقات في Edge. | يفتح التطبيق في نافذة مستقلة بعنوان Takeoff، ويظهر manifest وservice worker في أدوات المطور. | لقطة من نافذة التطبيق ولقطة من لوحة Application. |
| Windows 10/11 + Edge | أعد تشغيل التطبيق المثبّت ثم افتح `/projects` دون جلسة. | تظهر بوابة تسجيل الدخول أو رسالة استعادة؛ لا تظهر صفحة فارغة ولا دائرة تحميل مستمرة. | تسجيل شاشة مدته 30 ثانية. |
| Android 8.0+ | نزّل أثر `takeoff-native-debug-apk` من تنفيذ GitHub Actions الناجح وثبّت `app-debug.apk`. | تظهر شاشة البدء، ويمكن فتح PDF محلي أو لوحة المزامنة. | رقم التنفيذ ولقطة لشاشة البدء. |
| Android + S Pen | افتح PDF، عاير مسافة، ثم أنشئ Area وCUTOUT وNOTE بالقلم؛ ألغ الرسم مرة واحدة براحة اليد أو بزر الإلغاء. | تُقبل نقاط القلم الفعلية، وتُلغى الضربة غير الملتزمة بوضوح، ولا يتغير الحساب عند الإلغاء. | تسجيل شاشة مع إظهار مصدر الإدخال. |
| Android + شبكة | اربط جلسة الجهاز، واستورد مشروعاً مملوكاً، ثم نزّل PDF ومراجعة مرجعية. | لا تظهر إلا المشاريع والوثائق المملوكة؛ تبقى الحالة المحلية سليمة عند انقطاع الشبكة. | فيديو قصير ووقت الاختبار. |

> لا يكفي المحاكي أو اختبار المتصفح لإثبات حساسية قلم S Pen أو سياسة تثبيت Windows المؤسسية؛ يظل جهاز فعلي تحت نظام وسياسات الهدف مطلوباً.
